# Q2 价值实测报告 · C3 反向检查还剩多少判别力

日期：2026-11-13
触发：评审包 §5 Q2 —— 「C3 的反向检查是否已经弱到没有价值？」
方法：构造 7 类真实形态，看 C3 是否放过。**不看代码，只看行为。**

## 实测矩阵

| # | 场景 | 结论 | 性质 |
|---|---|---|---|
| P0 | 文档完全没提（正控） | **FAIL** ✅ | 反向检查确实在跑 |
| S1 | 文档写「本次不修改 ghost.js」 | pass | **假阴性**：声明不改、实际改了，却被当作已披露 |
| S2 | 无关叙述里提到（「上一版本的 ghost.js…」） | pass | **假阴性**：历史背景 ≠ 本次披露 |

## 实测中发现的真实缺陷（已修）

**S4 修复前 FAIL**：`listArtifacts` 把 specs 单独放在 `art.specs` 数组里，
而 C3 的 `allArtText` 只遍历 `ctx.art.files`（proposal/design/tasks），**根本没读 specs**。

而代码注释写的是「文档全文（含 design/proposal/specs）都找不到这个文件名才算没提」。

**注释比实现更宽** —— 在 specs/spec.md 里正常披露的新增文件会被判「改了但文档没提」。
这是假红：方向安全（不会造成假绿），但它让弱检查变成噪音，而噪音的结局通常是被整条关掉。

修复：`allArtText` 追加 `ctx.art.specs`。修后 S4 转 pass，回归全绿。

## 回答 Q2：还剩多少价值

**三个真阳性（P0/S3/S6）说明它不是零价值**，但**三个假阴性（S1/S2/S5）说明它的判据太粗**：

当前实现是 `allArtText.includes(basename)` —— 一次**无上下文的子串匹配**。它无法区分：

- 「我要改它」 vs 「我不改它」（S1 反了）
- 「本次涉及」 vs 「历史背景」（S2 无关）
- 「这个 ghost.js」 vs 「那个 ghost.js」（S5 同名不同目录）

## 结论：弱检查有价值，但价值点不在"覆盖"而在"兜底"

它现在的实际能力是：**只要有人在新文件的名字上完全不留痕，就会被抓**。
这是最低限度的保险 —— 对应「偷偷加了计划外文件」这一种情况。

它做不到的：判断文档里那句话是不是在说这个文件。
而这恰恰是判断"是否真的披露"所需要的。

## 建议（不是必须做）

**不要加强判据**，而应**改文案**。理由：

1. 加强判据需要语义理解（判断一句话是不是在说"本次要改它"），那就不是启发式能做到的了，
   强行加强只会重演 Q1 的六个后门（为了消误报而加豁免，结果造出新的绕过面）。
2. 当前的真实分工是：**C1 管硬约束**（allowedPrefixes + 行数预算），**C3 反向只做兜底提示**。
   评审包 §5 Q2 自己也说「这是否意味着 C3 的反向检查已经弱到没有价值」——
   答案是"弱，但按设计它就该弱"。
3. 真正该修的是**文案欺骗**：现在 pass 时打印
   「N 个变更文件均可在文档中找到出处」，这句话暗示"文档确实说了"，而实际只证明"名字出现过"。
   这与项目一贯反对的"以肯定句式掩盖"同型。

因此建议把 pass 文案改为：

  `N 个变更文件名均可在文档中找到（仅做名称匹配，不判断上下文）`

并保留现有的 fail 报错不变（fail 方向是准确的：名字完全没出现）。
