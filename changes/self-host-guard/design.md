# 设计：sdd-guard 自举

## 复用清单

| 现有模块路径 | 能复用什么 |
| :-- | :-- |
| `lib/contract.mjs` | 选项/档位/证据键的单一真源，自检脚本据此拼参数 |
| `lib/args.mjs` | 可重复键解析（`--code` 累积），不重写参数解析 |
| `lib/evidence.mjs` | 证据解析器与 provenance 指纹 |
| `lib/code.mjs` | 嵌套深度与重复块扫描，自身代码也走同一函数 |
| `test/mutation.mjs` | 变异负控，用来验证改判据后仍有判别力 |

## 结构决策

不新增目录、不新增依赖。改动集中在四处：

1. `lib/code.mjs` 的 `nestingDepth`：把「所有 `{` 计数」改成「只计控制流/函数体块」，
   对象字面量与数组字面量不计。判据语义因此更贴合「逻辑复杂度」这个原意。
2. `cli.mjs` 的参数选择：把「未知 id」与「不属于当前档位」分成两类错误，
   两者都退出码 2 —— 因为组合后为空集与拼错 id 是同一个失效模式：**跑了 0 条却报成功**。
3. 投机标记的模式表从代码移到数据文件：写在 `.mjs` 里时，模式字面量本身会被 `YAGNI-C1`
   当作违例（检测器自指误报）；数据文件不在 `CODE_EXT` 内，永不被当作源码扫描。
4. `tools/self-check.mjs` 的默认验收目标从夹具改为 sdd-guard 自身，
   否则「自检」跑的是夹具，自举名不副实。

## 接口契约

前后端在这里没有前端；本项目唯一的对外契约是 CLI 与证据文件，其**机器可读真源**在 `lib/` 下：

| 契约文件 | 内容 |
| :-- | :-- |
| `lib/contract.mjs` | 选项表、退出码、四态、配置默认值、档位、证据键 |
| `lib/evidence.mjs` | 证据 schema 的三个键与 provenance 字段 |

## 契约文档与真源的关系

ICD 是上述真源的人类可读投影（不是第二份契约），由 `tools/check-contract.mjs` 双向校验：
任何一侧改动而另一侧没跟上，检测即报漂移。因此**契约路径只登记 `lib/` 下的两份真源**，
文档不登记为契约——契约只能有一份真源。

| :-- | :-- |
| 无 | 不需要 |

## 风险与回退

- 判据语义变化可能削弱检出 → 用**成对正负控**锁定：对象字面量正控（必须 pass）+ 控制流 4 层负控（必须 fail），
  再加变异 `M6 嵌套深度判据失效` 证明判据仍依赖实现。
- 参数错误分类变化会改变退出码 → `test/args.test.mjs` 覆盖 `selectRules` 三分类。
- 模式表移到 json 后若加载失败，`SPECULATIVE_PATTERNS` 会抛错而不是静默变空——宁可启动失败，不可静默放行。
