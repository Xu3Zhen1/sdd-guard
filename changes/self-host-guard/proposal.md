# 提案：让 sdd-guard 用自己检查自己（self-host）

## 问题

sdd-guard 已经把「软倡议 → 硬判据」做出来了，但它自己**从未被自己检查过**：
`changes/` 目录不存在，`node cli.mjs check` 从没在 sdd-guard 自己的代码上跑过。
结果就是"教别人守规矩、自己不守"——本工作区已发生过两轮返工（`--code` 可重复失实、`--only` 静默空集）。

## 本次要做的

1. 用 `--profile process` 与 `--profile acceptance` 检查 sdd-guard 自身，记录首轮真实违例。
2. 修掉检查中发现的**假绿通道**（`--only` 与 `--profile` 组合后为空集仍退出 0）。
3. 修掉检查中发现的**误报**：`KISS-C1` 把对象字面量也算作嵌套。
4. 补上本次变更的四制品，使 process 档能自我关闭。

## 非目标

| 不做的事 | 为什么不做 |
| :-- | :-- |
| 不做 AST 级嵌套/重复分析 | 需要引入解析器依赖，与"零依赖"冲突；当前行级启发式已能覆盖控制流场景，先证明有用再换 |
| 不做 DSH 插件封装 | 插件形态需要 profile 挂钩与工具 schema，属于独立变更；本变更只证明"能自查" |
| 不调低 `maxNesting` 默认值或改用豁免绕过 | 那是把判据改软来迁就代码，属于 Goodhart 行为；真问题是判据把对象字面量误算成嵌套 |
| 不改 `ACCEPT-E*` 的证据语义 | 证据链刚闭环并有负控保护，本变更不动它 |

## 预期收益

- 首次有**自举证据**：判据在自己仓库上跑通，且过程中真抓到 2 个缺陷（1 假绿 + 1 误报）。
- 这些缺陷都是"检查器自身的可信度"问题，外部夹具永远暴露不出来。
